GitHub App transport (explicit opt-in; not operational wiring)

Construct InstallationAuth(app_id, installation_id, key_path, repos, 'read', installation_transport) and pass it as auth= to GitHubReadOnly. Construct a separate InstallationAuth with purpose 'publish' for a write-scoped token; never pass it to GitHubReadOnly. These objects are not wired into the worker or publisher. No review-posting lock is changed. Use separate processes/identities and key access controls for meaningful isolation; Python object separation is not a security boundary.

Network requests use a fresh isolated Python subprocess, stdin JSON credentials, bounded IPC and a 15-second supervision deadline with process-group termination and reaping. If group termination fails, the leader is killed separately where possible, but termination of group descendants cannot be guaranteed, particularly on permission failure. Cleanup waits at most one second for the leader; it may remain alive or unreaped if termination or the wait fails. Only HTTPS api.github.com is used and redirects are rejected. Errors are generic; do not log tokens, JWTs, response objects, traceback locals, HTTP debug output, or process memory. As with OS process scheduling and uninterruptible kernel operations, wall-clock cleanup cannot be guaranteed absolutely.

InstallationAuth checks repository ID and full name, expiry and exact permissions in the token response. It reloads the supplied policy at each request and again immediately before issuance; pass a shared mutable mapping or a policy file, not a stale copy. Policy changes can still race with an in-flight issuance after the final check. GitHubReadOnly rechecks current repo identity. Local policy changes cannot revoke already-issued tokens; they remain valid until expiration unless revoked externally. Transport inputs and auth objects are trusted in-process, not a security boundary.

GH CLI removal path: the explicit App-authenticated current() uses only the supplied read token and does not invoke gh. In this mode diff() deliberately fails closed: the current git fetch uses ambient GH_TOKEN/GITHUB_TOKEN and gh configuration, and repository name-based fetching has a rename/transfer race. Before enabling diff, design an isolated short-lived read-only Git credential channel without argv, URL, inherited gh config or environment leakage; establish GitHub's required contents permissions and bind repository identity for the entire fetch, or fail closed. The legacy default current()/diff() still use gh and may inherit broad credentials; migrate callers explicitly and disable legacy operation in deployment. No App-authenticated diff, write HTTP adapter, credential lifecycle/revocation service, live GitHub interoperability test, or production configuration is included.

GraphQL node-ID investigation (read-only; no credentials)

GitHub documents REST node_id to GraphQL direct node lookup, not a Git object hash: https://docs.github.com/en/graphql/guides/using-global-node-ids . ID format migration must be handled: https://docs.github.com/en/graphql/guides/migrating-graphql-global-node-ids . A node lookup does not by itself prove all later objects or PR data are bound to that repository throughout a request. The documented Tree.entries is nullable and not a connection with a completeness flag; Blob text can be unavailable or truncated: https://docs.github.com/en/graphql/reference/git . Ref.compare is not documented to supply the unique Git merge base: https://docs.github.com/en/graphql/reference/commits . Limits and partial GraphQL errors must be handled: https://docs.github.com/en/graphql/overview/rate-limits-and-query-limits-for-the-graphql-api .

An unauthenticated POST to https://api.github.com/graphql for octocat/Hello-World returned HTTP 403; the public REST tree https://api.github.com/repos/octocat/Hello-World/git/trees/master?recursive=1 returned one README and truncated=false. This does not verify GraphQL behavior, cross-fork access, or a safe ID-bound diff. REST tree URLs use mutable repository names and are not a replacement for identity binding; REST recursive tree truncation is documented at https://docs.github.com/en/rest/git/trees .

Required before enabling: authenticate only with isolated read credentials; pin and verify the repository node identity and PR base/head including fork access; retrieve and hash-verify complete commit graph, trees and blob bytes (including modes, symlinks and gitlinks), reject partial/error/truncated data and ambiguous or missing merge bases; enforce total byte, object, recursion, storage and time budgets; compare output byte-for-byte against local git diff with the same options across binary, attribute, encoding and criss-cross cases; recheck PR and live policy, and fail closed on any uncertainty. Pre/post checks cannot close an ABA race or make policy revocation atomic. Exact Git output requires reproducing its configuration and attributes; GraphQL text alone is insufficient for arbitrary blob bytes. No production implementation or claim of equivalence is made.
