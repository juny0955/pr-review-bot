# Repository policy

`repos.json` is the durable policy. Each entry has a positive integer GitHub repository `id`, exact `full_name`, and boolean `enabled`. IDs and names must be unique (names case-insensitively); malformed policy fails closed. Copy `repos.example.json` to the ignored `repos.json` and replace the example with the actual repository ID and name. Verify IDs independently using `gh api --method GET repos/OWNER/REPO --jq '{id,full_name}'` before adding repositories.

The receiver uses `REPO_CONFIG` (default `repos.json`) instead of `ALLOWED_REPOS`. Pass the same path as the required `repos` argument to `Worker` and `GitHubReadOnly`. It is re-read for authorization, so a disabled entry stops subsequent checks. Update the file atomically in a trusted directory; this policy is security-sensitive. A rename or transfer requires explicitly updating `full_name` while retaining the verified ID; queued events with the old name will be skipped. Name matching is exact. The GitHub adapter also verifies the PR API's base repository ID, preventing a reused name from authorizing a different repository. Configuration changes are not atomic with an already-running model call; stop workers before changing policy if a hard cutoff is required.

Live publication is disabled, including direct publisher calls: approval and policy revocation are not serialized with the GitHub POST. Before enabling it, implement a shared cross-process lock used by every publisher and every approval/policy revocation writer, held from final authorization through POST completion; revocation completes only after acquiring that lock and durably committing the change. Define recovery for crashed processes and uncertain POSTs. This cannot make GitHub and local state atomic, cancel an in-flight POST, or prevent administrators changing GitHub outside that lock. Old running code must also be stopped before relying on the disabled gate.

Operational deployment requires a separate publishing account with minimum GitHub permissions and repository access, independent of the read/model account. This code does not enforce account separation or permissions. Results lacking their original repository ID cannot be published and must be regenerated; never infer it from a queued event.
